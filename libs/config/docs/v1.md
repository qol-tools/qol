# QoL Config v1

`qol-config.toml` is the plugin-authored configuration contract for the QoL ecosystem.

## Goals

- one author-facing config file per plugin
- declarative data, not executable config
- stable validation in CI
- normalized form output for `qol-tray`

## Authoring Model

Each plugin may ship:

- `plugin.toml`
- `qol-config.toml`

`qol-tray` owns user overrides outside the plugin repo. Effective config is:

- defaults from `qol-config.toml`
- merged with tray-owned user overrides
- stale override keys are ignored
- invalid override values are rejected during normalization

## Top-Level Keys

- `schema_version`
- `title`
- `description`

## Tables

- `[section.<id>]`
- `[field.<id>]`

Section ids and field ids are unique within the file.
Section order and field order are preserved from author input.

## Sections

Supported section keys:

- `label`
- `description`
- `actions`
- `platforms`

Example:

```toml
[section.snap]
label = "Snap"
actions = ["snap-left", "snap-right", "snap-bottom"]
```

## Fields

Every field requires:

- `type`

Supported common field keys:

- `config_key`
- `label`
- `description`
- `placeholder`
- `section`
- `default`
- `option_labels`
- `card_description`
- `item_label`
- `lookup_label`
- `option_pictures`
- `lists`
- `show_when`
- `platforms`

Supported field types in v1:

- `boolean`
- `string`
- `number`
- `select`
- `string_array`
- `object_array`
- `object_map`
- `color`
- `placement`
- `action`
- `list`
- `status`
- `qr_code`
- `gamepad`
- `display_layout`

`action`, `list`, `status`, `qr_code`, `gamepad`, and `display_layout` are runtime-only fields and do not write user configuration. A `gamepad` field renders the browser's standard controller input model directly. It may reference an optional runtime `query` that supplies native button overrides when a browser omits controller inputs. A `display_layout` field renders the native settings panel's arrangement canvas; it must declare `query` and `active_query` referencing runtime queries and `action` and `active_action` referencing runtime actions.

A `placement` field stores where something appears on a screen as a string: one of the nine named spots `top-left`, `top-center`, `top-right`, `center-left`, `center`, `center-right`, `bottom-left`, `bottom-center` and `bottom-right`, or `x,y` fractions between 0 and 1 for a free spot, such as `0.25,0.6`. Its default must be one of those forms. The native settings panel edits it on a card that shows the active display: dragging the preview snaps it to the named spots, and holding it still for two seconds lets it go anywhere.

### Number Fields

Supported extra keys:

- `min`
- `max`
- `step`

A number field with `variant = "slider"` draws one field filled to the value: drag anywhere on it to adjust, or click it or press ↵ to type a number.

A number field without `min` is bounded below by 0, and one without `max` is bounded above by 2147483647, the largest `i32`. Validation and the settings panel use the same bounds, and the panel caps a typed value at `max` as it is typed. While a typed value is capped at `max`, or is below `min`, the field names that limit beside it, such as `max 90`.

A number field with `variant = "level_slider"` draws the wide slider as a row of level segments, lit green up to the level and turning yellow past 70 percent of the track and red past 90 percent, and must declare both `level_query` (a runtime query) and `level_value_from` (the key in that query's JSON object). The value is read as 0.0 to 1.0, clamped, with a missing or null value read as 0. The native panel polls `level_query` every 100 ms while the page showing the field is visible. Any other variant refuses `level_query` and `level_value_from`.

```toml
[field.volume]
type = "number"
default = 0
min = 0
max = 100
variant = "level_slider"
action = "set_volume"
active_query = "volume"
active_value_from = "volume"
level_query = "levels"
level_value_from = "output"
```

### Select Fields

Required extra key:

- `options`

Optional extra key:

- `[field.<id>.option_labels]`

Example:

```toml
[field.center_mode]
type = "select"
options = ["pixels", "percent"]

[field.center_mode.option_labels]
pixels = "Fixed Size"
percent = "Relative Size"
```

### Card Copy and Pictures

Fields that open a card carry the card's copy:

- `card_description` is the card sub header, a sentence in sentence case with a
  period, at most 36 characters. A field that opens a card is a `select`, an
  `object_array`, an `object_map`, a `string_array` with no `options` and no
  `query`, a `list`, a `display_layout`, a `gamepad`, a `qr_code` or a
  `placement`.
- `item_label` names one item in the card, at most 24 characters. It is valid on
  `object_array`, `object_map` and `string_array` fields.
- `lookup_label` names what a looked-up `select` is still finding, at most 24
  characters. Until the query answers, its card shows a waiting tile named
  "Looking for {lookup_label}".
- `option_pictures` maps every option of a `select` (from `options` and
  `option_labels`) to a picture spec.
- `[field.<id>.lists.<key>]` names a nested `string_array` under `item.fields` or
  `entry_fields` whose key does not end in `_mods`; it carries `item_label` and
  `card_description`, and the description may use the literal placeholder
  `{entry}`.

Example:

```toml
[field.action_mode]
type = "select"
card_description = "What letting go of the hotkey does."
options = ["hold_to_switch", "sticky"]

[field.action_mode.option_pictures]
hold_to_switch = "hold-to-switch"
sticky = "sticky"
```

A picture spec is `name` or `name:argument`. The names and their arguments:

- `icon-corner`: `left` or `right`
- `aa`: an integer from 8 to 48
- `desktop-theme`: `bone` or `slate`
- `web-theme`: `slate` or `midnight`
- `swatch`: `amber`, `green`, `cyan`, `magenta`, `blue` or `violet`
- `letters`: 1 to 3 characters with no whitespace
- `preset`: two integers from 0 to 100 joined by a comma
- `format`: 1 to 5 characters with no whitespace
- `terminal-session`: 1 to 24 characters
- `local-engine`: 1 to 12 characters
- every other name takes no argument

`qol_config::contract::PICTURE_NAMES` lists every name. A looked-up option
object may carry `"picture": "<spec>"` next to `value`, `label` and `accent`;
the panel draws it on the option tile and falls back to a letter tile when the
key is absent.

### Conditional Visibility

Fields may declare:

- `[field.<id>.show_when]`

Supported keys:

- `field`
- `equals`

Example:

```toml
[field.center_width_px.show_when]
field = "center_mode"
equals = "pixels"
```

`show_when` references another field id and compares against that field's current value.

### Per-OS Visibility

Fields and sections may declare:

- `platforms = ["linux", "macos", "windows"]`

The names are the ones `plugin.toml` uses in `platforms`.
Omitted means every OS.
The native settings panel neither draws nor searches a field or section whose `platforms` leaves out the running OS; a section's list also hides every field in it.
Gate a field this way when it only works on some operating systems, so its text never has to name one.
Stored values for a hidden field are kept.

Example:

```toml
[field.reveal_taskbar_after_move]
type = "boolean"
default = true
platforms = ["linux"]
```

## Example

```toml
schema_version = 1
title = "Window Actions"
description = "Window sizing and movement behavior."

[section.center]
label = "Center"
description = "Default centered window size."
actions = ["center"]

[field.center_mode]
type = "select"
label = "Sizing Mode"
section = "center"
default = "interpolate"
options = ["fixed", "percent", "interpolate"]

[field.center_width_px]
type = "number"
label = "Width"
section = "center"
default = 1152
min = 200

[field.center_width_px.show_when]
field = "center_mode"
equals = "fixed"

[field.center_height_px]
type = "number"
label = "Height"
section = "center"
default = 892
min = 200

[field.excluded_apps]
type = "string_array"
label = "Excluded Apps"
default = []
placeholder = "Bundle ID or app id"
```

## Validation Rules

v1 should reject:

- unsupported `schema_version`
- unknown field types
- duplicated section or field ids
- invalid section action ids
- duplicated section action ids
- field `section` references to missing sections
- unknown OS names in `platforms`, and an empty `platforms` list
- `select` fields without `options`
- invalid default type for the declared field type
- invalid override type for the declared field type
- select values not present in `options`
- numeric values outside `min` and `max`
- numeric constraints where `min > max`
- `step <= 0`
- empty `options`

## Normalized Output

The normalized form exposed to `qol-tray` should contain:

- title
- description
- ordered sections
- section actions
- ordered fields
- field id
- field type
- label
- description
- placeholder
- current value
- default value
- constraints
- options

`qol-tray` should render the normalized output rather than reinterpreting raw TOML directly.
